# IC014: an audit of SING's null-space leakage score

This repo holds the code, committed result tables and the paper (`paper_workshop/main.tex`, TMLR format; `main.pdf`) auditing SING (arXiv 2603.14610, CVPR 2026).

**Main finding: SING's cross-model leakage ranking is indistinguishable from a null-energy ranking.** The null-energy fraction ρ alone reproduces SING's 13-model order as well as SING's own score (Kendall τ = 0.82 for both; paired difference CI [−0.36, 0.29]; partial τ 0.61 both ways, so neither subsumes the other).
Interventions (rounds 3 and 4) show that AS has a path from null energy to the score that carries no image-specific content. They cannot separate null energy from real null content as the source of the agreement. Content-free surrogates with each model's null energy reproduce SING's order (τ 0.49–0.72 over five surrogates, all 13 models), and so does the excess of real over surrogate AS (τ 0.62). The data cannot apportion the order between the two. AS per unit null energy (A1) loses the agreement with SING's released translators (τ −0.03 / 0.09 on E12 / S11) but keeps it with retrained ridge translators (τ 0.61 / 0.75, the level of the round-3 KILL-R3 rule). Shuffling class means across classes, which preserves energy exactly, keeps the agreement (τ 0.64), which leans toward energy, with a caveat: the class-aligned part Δ_align has the stronger partial association given ρ (partial Spearman 0.76–0.88 vs 0.22–0.35), and Δ_align fails its own calibration; the pre-registration allows no stronger claim than these raw numbers. In semi-synthetic calibration worlds no estimator meets all three criteria; the translator-free NCM_null tracks content in two of the three worlds (M and D).
Other results: two true DINO models rank 8th and 9th of 15 by AS, not lowest; SING's "DinoViT" translator matches the supervised timm AugReg ViT-L/16. Size-corrected rankings differ from SING's but do not reverse it with confidence. Every pre-registered outcome is reported, including failures; see `RESULTS.md` and the ledgers in the paper appendix.

## Layout
* `exp0b/` DinoViT identity (top-1 of five ViT-L candidates). `exp0/` digitisation of SING Supp. Fig. 12b (files keep an earlier name, `fig6b_*`) and null dims. `exp1/` within-model AS(d).
* `e1/` energy law; `e2/` 13-model ranking and claim audit; `e3/` planted-concept sensitivity; `e8/` null concept probe (pre-registered, KILL); `e9/` score screen (pre-registered, KILL).
* `r2/` round-2 analyses (`PREREG_R2.md`, `ROUND2_PLAN.md`); outputs in `r2/results/`. See `r2/README.md`.
* `r3/` round-3 analyses (`PREREG_R3.md`, `ROUND3_PLAN.md`): equal-energy interventions, leak-free null, retrained translators, PC bands vs the energy law, paired statistics, table generation. See `r3/README.md`.
* `r4/` round-4 analyses (`PREREG_R4.md`, `PREREG_R4B.md`, `PREREG_R4C.md`, `ROUND4_PLAN.md`): surrogates, A1 statistics, retrained A4, planted content, true DINO, class-mean permutation, calibration worlds, selectivity, NCM_null, NZS, geometry. See `r4/README.md`.
* `paper_workshop/tables/` LaTeX tables and number macros generated by `r3/make_tables.py` and `r4/make_tables_r4.py` (do not edit by hand).
* `gpu_jobs/` specs for work that needs ImageNet images or a GPU.
* `paper_workshop/archive/` earlier drafts.

## Reproduce
Environment: `python -m venv v && v/bin/pip install -r requirements-pinned.txt` (exact versions of the direct dependencies, CPU torch, Python 3.13; checked in a fresh venv with `scripts/reproduce.sh`). `requirements.txt` gives looser ranges; `requirements-lock.txt` is the old whole-machine freeze, kept for reference only.

* `make reproduce` (or `scripts/reproduce.sh`) regenerates every table, figure and number macro in the paper from **committed aggregate results** (round-2 summaries, `r3/results/F_paired_stats.json`, round-4 macros and tables, `paper_workshop/figs/`, `paper_workshop/tables/`, `paper_workshop/holdout_numbers.tex`). CPU, about 20 s. This checks consistency from aggregates only; it does not recompute anything from features. In a clean clone, `bash scripts/reproduce.sh && git diff --exit-code` passes.
* `make reproduce-r4 IC014_FEATS=/path/to/feats` reruns the round-4 feature-level analyses (see `r4/README.md`); the true DINO features come from a GPU extraction.
* `make paper` builds the PDF with tectonic (`tectonic -X compile main.tex`).
* `make reproduce-full IC014_FEATS=/path/to/feats` reruns the feature-level analyses (rounds 2 and 3). It needs the private ImageNet features (checked by `scripts/verify_feats.sh` against `scripts/checksums.sha256`) and SING at commit e47b37d (`scripts/fetch_sing.sh`). There is no default feature path; a missing `IC014_FEATS` stops with an error. Per-image private outputs go to `IC014_PRIVATE` (default: the git-ignored `_private/`), never to the feature store.
  * Wall time on 8 CPU cores: a little over 2 h, most of it the E9 holdout (full run 1.95 h, about 7000 s); everything else takes about 15 min.
  * `make holdout-fast IC014_FEATS=...` runs the reduced holdout declared in `PREREG_R3.md` (N10): 5 draws instead of 20, 2 subspaces instead of 5, S9 dropped; resumable from its cache (checked: a run restarted from 40 of 64 cached cells skips them and ends with an identical cache and results). Timed on 8 cores: 36.3 min (target was under 30 min, missed; the machine was shared with other jobs, load not recorded, and it was not re-timed in round 4). M1 and AS_SING Kendall means and all flatness verdicts are identical to the full run; AS_fair differs by +0.024 (linear) and +0.057 (nonlinear), and M1 − AS_fair by −0.024 / −0.057, so the nonlinear values miss the ±0.03 target. Use the full run for the paper numbers.
* **GPU work** (feature extraction; needs ILSVRC2012-val): two jobs were timed, Exp 1 features (1.4 GPU-h, one cloud GPU) and the fix-14 ViT-L/16 re-extraction (1.9 h on 2× T4 ≈ 3.8 GPU-h including weight downloads). The other extraction jobs were not timed; we estimate under 10 GPU-h in total. Specs are in `gpu_jobs/` (including the not-yet-run `gpu_jobs/r3_dino_vitb16.md`).

## Data
We do not redistribute ImageNet images or features derived from them (ImageNet terms of access).
The image lists are in `scripts/subset_files_10k.txt` (10 per class, file name and label) and `scripts/subset_files_claims200.txt`. Re-extracting the features requires your own copy of ILSVRC2012 val.
